# Правила классификации конкурентов

Источник истины по критериям — `business_context.json` (поля `searchCriteria.include/exclude`,
`competitors.classificationRules`). Настоящий файл описывает базовые правила,
применяемые, если карточка задаёт их частично или не задаёт вовсе.

## Обязательное условие для любого типа

У кандидата **обязательно** должно быть действующее открытое сообщество VK.
Кандидаты только с сайтом (без VK) исключаются с причиной `no active VK community`.
Если у конкурента есть и VK, и сайт — в итоговом списке указываются обе ссылки.

## Типы конкурентов

| Тип | Определение | Признаки |
|-----|-------------|----------|
| `direct` | Прямой конкурент: тот же продукт/услуга, та же аудитория, тот же ценовой сегмент и модель продаж | Совпадает ассортимент (ключевые слова include в названии/описании и подтверждение по постам), география, сегмент |
| `indirect` | Косвенный: пересекается аудитория или часть ассортимента, но отличается формат/сегмент/масштаб | Частичное совпадение keywords; например, агрегатор курсов вместо конкретной школы |
| `attention` | Конкурент внимания: борется за то же время/бюджет подписчика, но не продаёт сопоставимый продукт | Образовательный/развлекательный контент для той же аудитории без продажи похожего продукта |

## Порядок присвоения типа

1. Проверить обязательное условие (VK-сообщество). Нет — исключить.
2. Сравнить ассортимент по собственным публикациям за окно (не только по описанию).
3. Применить исключения карточки (`exclude`) — при срабатывании кандидат исключается независимо от типа.
4. Оценить аудиторию, географию, ценовой сегмент, модель продаж, производство (если критерий важен для бизнеса), онлайн/офлайн-формат.
5. Все ключевые измерения совпадают → `direct`; 1–2 существенных отличия → `indirect`;
   совпадает только аудитория/тематика → `attention`.
6. Для каждого кандидата заполнить поля квалификации (`assortment`, `audience`, `geography`,
   `price_segment`, `sales_model`, `production`, `format`, `why_competitor`, `sources_checked`).

## Правило недостатка кандидатов

Если подходящих конкурентов меньше целевого числа (`searchCriteria.count`), критерии
самостоятельно НЕ ослабляются. Фактическое количество и причины дефицита фиксируются
в `run_manifest.json` (поле `shortfall`) и на листе «Сводка».
