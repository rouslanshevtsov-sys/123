# Навык: vk-competitor-orchestrator (управляющий агент цепочки VK)

## Назначение и границы

Организует полную цепочку анализа VK-конкурентов, запуская навыки **только из
`.agents/skills`** в правильном порядке и передавая результаты между этапами.

Цепочка: `business-context-interview → search-vk-competitors → analyze-vk-best-posts → vk-content-report`.

Управляющий агент **только маршрутизирует**: определяет этап, проверяет готовность
входов, запускает навык, контролирует gate-проверку, переиспользует валидные результаты.

Управляющий агент **не должен самостоятельно**: проводить интервью; искать конкурентов;
собирать публикации; рассчитывать ER; обрабатывать медиа; анализировать рынок; создавать
предметные отчёты. Всё это — ответственность соответствующих навыков. Предметная логика
в скриптах orchestrator отсутствует: проверки результатов выполняются нативными
валидаторами навыков (`scripts/run_stage.py` вызывает gate каждого навыка).

## Правила маршрутизации

1. **Бизнес-контекст.** Перед любой задачей, зависящей от данных бизнеса, проверь
   `business_context.json` (`scripts/check_inputs.py`). Отсутствует / повреждён /
   не `confirmed` → запускай `business-context-interview`. Не проводи интервью повторно
   при валидном подтверждённом контексте; повторный запуск — только по прямой просьбе
   обновить контекст.
2. **Поиск конкурентов.** Запускай `search-vk-competitors` **только по прямой просьбе**
   (найти/проверить/обновить список конкурентов). Просьба подготовить недельный отчёт —
   НЕ разрешение на поиск. Нет валидного `competitor_set.json` → остановись и запроси
   отдельное разрешение.
3. **Недельный отчёт.** Порядок: проверить `business_context.json` → найти последний
   валидный `competitor_set.json` → `analyze-vk-best-posts` (окно по умолчанию 7×24 ч,
   Europe/Moscow) → дождаться успешной проверки и **медиашлюза** → `vk-content-report`.
4. **Ошибки и остановки.** Не запускай следующий этап, если предыдущий завершился с
   ошибкой, не прошёл проверку/gate, создал повреждённые результаты или требует
   подтверждения пользователя. Деградированный медиарежим разрешай только после явного
   согласия пользователя (`run_stage.py --allow-degraded`, согласие фиксируется в
   `degraded_media_consent.json`; без него `check_inputs.py --stage report` блокирует этап).

Запуск этапов — `scripts/run_stage.py`; разбор запроса — `scripts/route_request.py`
(намерения: interview / competitors / weekly report / analyze posts / market reactions /
refresh context). Скрипты возвращают коды: 0 — можно продолжать, 1 — ошибка этапа,
2 — остановка/подтверждение, 3 — нет переиспользуемого результата.

## Управление данными и состоянием запусков

- Каждый запуск — уникальный каталог `runs/YYYY-MM-DD/<run-id>/` (`scripts/create_run.py`).
  Результаты предыдущих запусков **не перезаписываются**; индекс `runs/index.json` — append-only.
- Между этапами передавай только compact JSON: пути файлов, статусы проверок, хэши входов
  (`handoff.json`, `gate_status.json`, `scripts/hashes.py`). Полное содержимое крупных
  файлов между этапами не передаётся — достаточно пути и краткого описания.
- Перед запуском этапа: рассчитай хэши входов → найди последний результат этапа
  (`scripts/find_reusable.py`) → проверь валидность (статус `pass` в индексе + артефакты
  на месте) → сравни хэши. Не изменились и результат валиден → **используй готовый**.
  Изменились или прошлый результат невалиден → новый запуск в отдельном каталоге.
- Условие успеха этапа для следующего шага — `scripts/check_stage_success.py`
  (последняя запись этапа в `runs/index.json` со статусом `pass`, проставляемым
  только при пройденном нативном gate навыка).

## Политика моделей

Перед запуском этапа читай [references/routing-policy.json](references/routing-policy.json)
и применяй указанную модель/effort (интервью — terra/medium; поиск конкурентов — sol/medium;
анализ постов — terra/medium; первый сложный анализ рынка — sol/high; регулярный анализ —
sol/medium). Значения моделей живут только в политике; в SKILL.md и скриптах не дублируются.

## Единая проверка цепочки

`python scripts/check_chain.py --root <workspace>` — структура workspace, пороги,
артефакты, медиашлюз, происхождение/хэши, секреты в runs/. Итог — compact JSON
со списком проверок и первой причиной остановки. Самоскан файлов навыка —
`python scripts/detect_secrets.py`. Тесты — `tests/test_routing_positive.py`,
`tests/test_routing_negative.py`.

## Безопасность токена и файлов

Токен VK API читают только навыки этапов (из `vk_token.txt`/env); orchestrator токен
не читает, не выводит и не включает в handoff. В файлах навыка запрещены абсолютные пути
и любые секреты. `runs/` и `vk_token.txt` — вне git (.gitignore).
