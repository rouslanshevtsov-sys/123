# Навык: Сбор и подтверждение бизнес-контекста

## Границы ответственности

Этот навык делает ТОЛЬКО этап 1: интервью, категоризация требований к конкурентам,
генерация и подтверждение `business_context.json` + `business_card.md` + `provenance.json`.
Поиск конкурентов, сбор постов и анализ реакций — отдельные навыки; они читают только
подтверждённый артефакт этапа 1 (порог входа — `common.require_confirmed_context`).

## Условия запуска / остановки

Запускать, если: просьба собрать бизнес-контекст / провести интервью; запрос «найди
конкурентов» при отсутствии валидного confirmed-контекста; явная просьба обновить контекст.
НЕ запускать, если: в рабочей папке уже есть `business_context.json` со статусом
`confirmed` и обновление не запрошено (проверка: `scripts/check_status.py --file … --expected confirmed`).

Остановка: карточка подтверждена и все проверки пройдены; пользователь отказался;
3 ошибки доступа к источнику подряд; критическая ошибка (сообщить пользователю).
Полные условия — `references/chain-contract.md` §7.

## Обязательные входы

1. Ссылка на сообщество VK (обязательно). Сайт и доп. источники — опционально.
2. Токен VK API — опционально; хранится ТОЛЬКО в `vk_token.txt` рядом с директорией
   запуска; файл обязан быть в `.gitignore`; токен не попадает ни в один артефакт.
3. Ответы пользователя на интервью — без них данные выдумывать запрещено
   (пустое поле = null/[] с меткой «⚠️ Не заполнено»).

## Порядок работы (ключевые решения)

1. Изучить источники (VK API/сайт); зафиксировать доступность и `source.parseError`.
2. Интервью о бизнесе — до 15 вопросов, по одному, с нумерацией; затем показать пробелы.
3. Вопросы о конкурентах — до 10 (критерии, география, лимиты, запросы поиска).
4. Генерация draft:
   `python scripts/generate_card.py --output-dir "<папка_запуска>" --data <input.json>`
5. Подтверждение пользователем → `python scripts/confirm_card.py --input-dir "<папка_запуска>"`
   (пересобирает MD из тех же данных, пересчитывает хэш и provenance — синхронность гарантирована конструктивно).
6. Итоговая проверка ОДНИМ прогоном: `python scripts/final_validation.py --dir "<папка_запуска>"`
   и `python scripts/detect_secrets.py --dir "<папка_запуска>"`.

Полный список вопросов, правила категоризации (direct/indirect/attention), этапы
подтверждения и детали полей — `references/card-structure.md`. Контракт передачи
следующим навыкам (артефакты, хэши, кэш, безопасность токена) —
`references/chain-contract.md`; пример сквозного прогона — `references/chain-example.md`.

## Результаты (передача дальше)

В `<папка_запуска>/`: `business_context.json` (confirmed + hashes), `business_card.md`,
`provenance.json` (compact summary ~1 КБ — его читает навык «Конкуренты», полный файл —
только точечно; кэш-проверка через `contextHash`).

## Скрипты

Единая точка правды схемы/хэшей/секретов — `scripts/common.py`; каждый скрипт тонкий:
- `generate_card.py` — draft + provenance; `confirm_card.py` — confirmed + пересчёт хэша;
- `validate_json_schema.py`, `check_status.py`, `check_required_fields.py`,
  `detect_secrets.py` (--file/--dir), `check_sync.py` — отдельные проверки (совместимость сохранена);
- `final_validation.py` — ВСЕ проверки за один проход, JSON-отчёт;
- `test_chain.py` — сквозной тест цепочки (без сети); `tests/` — pos/neg тесты.

## Примечания

Навык не содержит данных конкретного бизнеса и секретов; пути относительные;
все новые поля схемы необязательны (обратная совместимость v1.0–v1.2 документов).
