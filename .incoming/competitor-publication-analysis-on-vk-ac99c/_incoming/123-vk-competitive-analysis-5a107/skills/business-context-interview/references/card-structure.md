# Структура карточки бизнеса

## Обязательные разделы и поля

### 1. Описание бизнеса

**Обязательные поля:**
- `name` — название бизнеса (string)
- `niche` — маркетинговая ниша (string)
- `positioning` — позиционирование (string, опционально)
- `description` — описание в 2-3 предложениях (string)

**Правила заполнения:**
- Название должно быть точным, как его знает бизнес
- Ниша — конкретная маркетинговая категория (не «бизнес», а «онлайн-образование для парикмахеров»)
- Описание должно отвечать на вопросы: что это? для кого? какую проблему решает?

### 2. Продукты и ассортимент

**Обязательные поля:**
- `main` — основные продукты (array of strings)
- `secondary` — второстепенные продукты (array of strings, опционально)
- `assortmentWidth` — широта ассортимента (string, опционально)
- `producer` — кто производит/поставляет (string)
- `productionType` — тип производства (string, опционально)

**Правила заполнения:**
- Основные продукты — то, что приносит основную выручку
- Второстепенные — дополнительные услуги, материалы, консультации
- Производитель — автор, команда, приглашённые эксперты, перепродажа

### 3. Аудитория

**Обязательные поля:**
- `targetSegments` — целевые сегменты (array of strings)
- `tasks` — задачи клиентов (array of strings, опционально)
- `painPoints` — боли клиентов (array of strings, опционально)

**Правила заполнения:**
- Сегменты — конкретные группы (не «все», а «начинающие парикмахеры», «владельцы салонов»)
- Задачи — что клиент хочет решить, покупая продукт
- Боли — проблемы, которые мешают клиенту

### 4. География

**Обязательные поля:**
- `regions` — регионы работы (array of strings)
- `format` — формат работы (string: онлайн, офлайн, гибрид)

**Правила заполнения:**
- Указывать конкретные страны, города или «весь мир онлайн»
- Формат — как работает бизнес (онлайн/офлайн)

### 5. Цены

**Обязательные поля:**
- `model` — модель ценообразования (string)
- `range` — диапазон цен (string, опционально)

**Правила заполнения:**
- Модель — подписка, разовая покупка, пакеты, freemium
- Диапазон — минимальная и максимальная цена

### 6. Процесс продаж

**Обязательные поля:**
- `orderProcess` — процесс заказа (string)
- `paymentMethods` — способы оплаты (array of strings)
- `deliveryOrAccess` — доставка или доступ (string)
- `salesFormat` — формат продаж (string)

**Правила заполнения:**
- Процесс — как клиент покупает (шаги)
- Способы — карта, СБП, рассрочка, криптовалюта
- Доступ — как клиент получает продукт (ссылка, личный кабинет, доставка)

### 7. Каналы

**Обязательные поля:**
- `acquisition` — каналы привлечения (array of strings)
- `onlinePresence` — присутствие в интернете (array of strings)

**Правила заполнения:**
- Привлечение — откуда приходят клиенты (VK таргет, рефералы, SEO)
- Присутствие — где бизнес представлен (сайт, соцсети, платформы)

### 8. Преимущества и ограничения

**Обязательные поля:**
- `advantages` — преимущества (array of strings)
- `limitations` — ограничения (array of strings, опционально)

**Правила заполнения:**
- Преимущества — что выделяет бизнес среди конкурентов
- Ограничения — что мешает или ограничивает

### 9. Ключевые особенности

**Опциональные поля:**
- `keyFeatures` — ключевые особенности (array of strings)

**Правила заполнения:**
- Уникальные характеристики бизнеса
- То, что нельзя отнести к преимуществам, но важно понимать

### 10. Конкуренты

**Обязательные поля:**
- `known` — известные конкуренты (array of strings)
- `classification` — правила классификации (object)

**Правила заполнения:**
- Известные — конкретные названия бизнесов
- Классификация — правила для трёх типов конкурентов (см. ниже)

### 11. Критерии поиска конкурентов

**Обязательные поля:**
- `mustHaveFeatures` — обязательные особенности (array of strings)
- `searchPlatforms` — платформы поиска (array of strings)
- `count` — количество конкурентов (string)
- `geography` — география поиска (string)
- `vkAudienceLimit` — минимальная аудитория VK (string, опционально)
- `publicationFreshness` — свежесть публикаций (string, опционально)
- `include` — кого включить (array of strings)
- `exclude` — кого исключить (array of strings)
- `searchQueries` — поисковые запросы (array of strings)

**Правила заполнения:**
- Обязательные особенности — что должно быть у конкурента
- Платформы — где искать (VK, GetCourse, YouTube)
- Количество — сколько конкурентов нужно найти
- География — в каких регионах искать
- Включить/исключить — конкретные бизнесы

### 12. Пробелы

**Обязательные поля:**
- `gaps` — оставшиеся пробелы (array of strings)

**Правила заполнения:**
- Список того, что не удалось выяснить
- Формулировки должны быть конкретными

## Правила категоризации конкурентов

### Прямые конкуренты

**Определение:**
Продают тот же продукт той же аудитории.

**Критерии:**
- Ассортимент может быть шире, но обязательно должен включать большинство позиций вашего бизнеса
- Основная специализация должна совпадать с вашим бизнесом
- Целевая аудитория — та же самая

**Пример:**
Если вы продаёте курсы по маркетингу для парикмахеров, прямой конкурент — другой бизнес, который продаёт курсы по маркетингу для парикмахеров (даже если у него больше курсов).

### Косвенные конкуренты

**Определение:**
Продают часть вашего ассортимента или похожий ассортимент.

**Критерии:**
- Не все продукты совпадают, но есть пересечение
- Аудитория может частично совпадать
- Ниша может быть смежной

**Пример:**
Если вы продаёте курсы по маркетингу для парикмахеров, косвенный конкурент — курсы по маркетингу для салонов красоты (смежная ниша) или курсы по парикмахерскому делу (смежный продукт).

### Конкуренты за внимание

**Определение:**
Бизнесы, которые могут отвлечь внимание вашего клиента, закрывая схожую потребность.

**Критерии:**
- Клиент может совершить покупку одновременно или в дополнение к покупке у вас
- Потребность схожая, но продукт другой
- Аудитория пересекается

**Пример:**
Если вы продаёте курсы по маркетингу для парикмахеров, конкурент за внимание — курсы по управлению салоном красоты (клиент может купить оба курса) или инструменты для парикмахеров (клиент может потратить бюджет на инструменты вместо обучения).

## Правила подтверждения бизнес-контекста

### Этапы подтверждения

1. **Генерация draft-версии**
   - Создай Markdown и JSON из собранных данных
   - Установи статус `draft`
   - Покажи пользователю

2. **Проверка пользователем**
   - Пользователь проверяет все поля
   - Если есть ошибки — вернись к интервью
   - Если всё верно — переходи к подтверждению

3. **Подтверждение**
   - Пользователь явно подтверждает карточку
   - Обнови статус на `confirmed`
   - Добавь дату подтверждения
   - Синхронизируй Markdown и JSON

4. **Финальная проверка**
   - Проверь синтаксис JSON
   - Проверь согласованность Markdown и JSON
   - Проверь отсутствие токенов/секретов
   - Проверь отсутствие придуманных данных

### Критерии подтверждения

Карточка считается подтверждённой, если:
- Статус: `confirmed`
- Дата подтверждения: заполнена
- Все обязательные поля заполнены (или явно отмечены как пробелы)
- Markdown и JSON синхронизированы
- Нет токенов или секретов в файлах
- Нет придуманных данных (только данные из интервью)

## Требования к согласованности Markdown и JSON

### Правила синхронизации

1. **Одинаковая информация**
   - Все данные в Markdown должны быть в JSON
   - Все данные в JSON должны быть в Markdown
   - Нет расхождений в значениях

2. **Одинаковый статус**
   - Оба файла имеют статус `confirmed` или `draft`
   - Оба файла имеют дату подтверждения (если статус `confirmed`)

3. **Одинаковая структура**
   - Разделы в Markdown соответствуют полям в JSON
   - Порядок разделов совпадает

### Проверка согласованности

Используй скрипт `scripts/check_sync.py`:
- Извлекает данные из Markdown
- Извлекает данные из JSON
- Сравнивает все поля
- Сообщает о расхождениях

## Минимальный набор обязательных полей

Для успешного подтверждения карточки должны быть заполнены:

1. `business.name` — название бизнеса
2. `business.niche` — маркетинговая ниша
3. `business.description` — описание бизнеса
4. `products.main` — основные продукты (минимум 1)
5. `audience.targetSegments` — целевые сегменты (минимум 1)
6. `geography.regions` — регионы работы (минимум 1)
7. `channels.acquisition` — каналы привлечения (минимум 1)

Остальные поля могут быть пустыми, но должны быть явно отмечены как пробелы в разделе `gaps`.
