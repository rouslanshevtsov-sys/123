# Отчёт по лучшим публикациям ВКонтакте (доказательный)

Принимает валидные результаты предыдущего этапа и создаёт короткий HTML-отчёт с выводами,
подкреплёнными ссылками на исходные публикации. Работает только с готовыми данными.

## Обязательные входные данные

Все файлы — в одной рабочей папке (`--workdir`). Пути в отчёте относительные.

| Файл | Что содержит | Проверка |
|---|---|---|
| `vk_posts_dataset.json` | все проанализированные посты конкурентов: метрики, ER, бенчмарк, rel, ссылки | поля, пересчёт ER, формат ссылок |
| `comments.json` | комментарии под этими постами | связь каждого post_id с датасетом |
| `competitors_vk_report.xlsx` | лист «Лучшие», лист «Проверенные» (+ сводки, клипы) | сверка post_id и значений с датасетом |
| `provenance.json` | sha256 всех входов, кто их создал, множество проверенных post_id | совпадение хэшей и множеств |
| `media/images/`, `media/transcripts/` | доступные изображения и расшифровки VK Клипов | наличие файлов для постов с медиа/клипами |

Нет файла, файл повреждён, хэш не сходится или множества post_id не согласованы —
**работа останавливается**, выводится причина (файл, post_id, ожидаемое и фактическое значение).
Дальнейший анализ «приблизительно» запрещён.

## Маршрут анализа

1. **Происхождение входа.** `python3 scripts/validate_inputs.py --workdir <wd>` — обязательные
   файлы, читаемость JSON/XLSX, sha256 из `provenance.json`, сверка множеств post_id
   (датасет ↔ комментарии ↔ XLSX), формат ссылок `https://vk.com/wall|clip-oid_pid`.
   Правила: `references/analysis-contract.md`.
2. **ER и бенчмарки.** `python3 scripts/validate_metrics.py --workdir <wd>` — ER =
   (лайки+комментарии+репосты)/просмотры; бенчмарк = средний ER постов своего сообщества;
   rel = ER/бенчмарк своего сообщества; клипы без просмотров — отдельным статусом.
3. **Комментарии → связи.** Тот же скрипт проверяет, что ≥90% комментариев привязаны к
   post_id датасета и что у клипов есть расшифровки.
4. **Классификация комментариев.** `python3 scripts/classify_comments.py --workdir <wd>` →
   `comment-signals.json` (структура: `references/comment-signals-schema.md`; правила:
   `references/comment-classification.md`). Спам-шаблоны исключаются из сигналов.
5. **Анализ всех проверенных постов.** `python3 scripts/analyze_posts.py --workdir <wd>` →
   `analysis-core.json`: сегменты верхних 25% и нижних 25% (`references/segmentation.md`),
   разделение ER-/CTA-/содержательных сигналов (`references/signal-separation.md`),
   агрегаты по сообществам, отдельный блок VK Клипов (`references/clips-rules.md`),
   компактный аналитический вход для модели.
6. **Выводы модели.** Модель читает `analysis-core.json` + `comment-signals.json` и пишет
   `report-draft.json` (схема: `references/report-draft-schema.md`). Приоритет опоры:
   сначала прямые конкуренты, при нехватке данных — косвенные, затем — за внимание
   (`references/competitor-priority.md`). Доказательность и цитаты:
   `references/evidence-rules.md`, `references/quotes-and-links.md`.
7. **Сборка отчёта.** `python3 scripts/build_report.py --workdir <wd>` → `report.html`
   по шаблону `templates/report-template.html` (смысловые блоки идут вертикально сверху вниз).
8. **Проверка результата.** `python3 scripts/validate_report.py --workdir <wd>` — структура
   (`references/html-structure.md`), объём (`references/report-length.md`), доказательства,
   кликабельные ссылки, отсутствие неподтверждённых причинных выводов, отсутствие рекомендаций
   (`references/no-recommendations.md`), изоляция VK Клипов, полная цепочка данных.
   Exit code 2 — правки обязательны до отдачи результата.

## Основные смысловые правила

- Отчёт разделяет четыре типа сигналов: ER-сигналы, CTA-сигналы, содержательные сигналы,
  сигналы из комментариев. Они не смешиваются в одном утверждении.
- Выводы только доказательные: наблюдение над данными, совпадение признаков, подтверждённая
  причинная связь. Причина успеха или провала публикации допускается лишь при данных
  (несколько постов одного паттерна, прямая цитата читателя, сопоставимые посты одного
  сообщества с rel ≥ 2x / ≤ 0.5x). Иначе пишется: «чем это вызвано, данные не показывают».
- Каждое утверждение о публикации сопровождается ссылкой вида
  `https://vk.com/wall-oid_pid` (для клипов `https://vk.com/clip-...`) и дословной цитатой.
- Числовые сравнения ER — только при двукратном отличии от бенчмарка; между 0.5x и 2x
  используется словесная формулировка «на уровне бенчмарка».
- VK Клипы анализируются отдельно от обычных публикаций и не попадают в сегменты ленты.
- Язык простой, короткие предложения, без ИИ-штампов (`references/plain-language.md`).
- Навык не ищет конкурентов, не дополняет выборку и не перечитывает VK через API.

## Условия остановки

Остановить работу и сообщить причину, если:
1. отсутствует или не читается любой обязательный вход (включая пустой `comments.json`);
2. хэш файла не совпадает с `provenance.json` или вход не описан в нём;
3. post_id из XLSX или комментариев отсутствуют в датасете, есть дубли post_id;
4. пересчитанный ER расходится с датасетом больше 0,5 п.п. или бенчмарк сообщества
   расходится со средним ER больше 2%;
5. у VK Клипов нет ни одной расшифровки;
6. отчёт нарушает структуру, объём, не имеет доказательств, содержит рекомендации,
   неподтверждённые причинные выводы или смешанные с лентой клипы
   (`scripts/validate_report.py`, exit code 2).

## Ожидаемые результаты

После полного прогона в рабочей папке лежат:
- `validation_inputs.json`, `validation_metrics.json` — протоколы проверок входа и метрик;
- `comment-signals.json` — классифицированные комментарии (без спама в сигналах);
- `analysis-core.json` — сегменты, разделённые сигналы, агрегаты, блок клипов;
- `report-draft.json` — выводы модели с доказательствами;
- `report.html` — итоговый отчёт: 900–1500 слов, вертикальные смысловые блоки, активные
  ссылки на публикации, без рекомендаций и контент-плана;
- `validation_report.json` — протокол финальной проверки (ok: true).
