# Навык: Сбор и подтверждение бизнес-контекста

## Назначение

Воспроизводит методику сбора полного контекста бизнеса для последующего поиска и анализа конкурентов. Включает изучение источников, проведение интервью, категоризацию конкурентов и генерацию синхронизированных файлов.

## Условия запуска

Запускай навык, если:
- Пользователь просит собрать бизнес-контекст
- Пользователь просит провести интервью о бизнесе
- Пользователь просит найти конкурентов (требуется контекст)
- Пользователь явно просит обновить существующий бизнес-контекст

**НЕ запускай навык, если:**
- В рабочем пространстве уже существует валидный файл `business_context.json` со статусом `confirmed`
- Пользователь не просил обновить контекст

## Обязательные входные данные

Перед началом работы запроси у пользователя:

1. **Токен VK API** (опционально, но рекомендуется):
   - Предложи ввести токен через скрытый ввод
   - Сохрани токен в файл `vk_token.txt` в рабочей папке
   - Если пользователь отказывается — продолжай без API

2. **Ссылка на сообщество VK бизнеса** (обязательно):
   - Пример: `https://vk.com/your_community`
   - Используй VK API для получения публичной информации

3. **Ссылка на сайт бизнеса** (опционально):
   - Если существует — изучи содержимое
   - Если нет — перейди к следующему шагу

4. **Дополнительные источники** (опционально):
   - Соцсети, блоги, статьи о бизнесе
   - Любые материалы, которые пользователь хочет учесть

## Порядок работы

### Этап 1: Изучение источников

1. Получи токен VK API (если предоставлен)
2. Изучи сообщество VK через API:
   - Название, описание, статус
   - Количество участников
   - Последние публикации
   - Контакты и ссылки
3. Изучи сайт (если предоставлен)
4. Изучи дополнительные источники
5. Собери всю доступную информацию о бизнесе

### Этап 2: Интервью о бизнесе (до 15 вопросов)

Задавай вопросы по одному, нумеруй каждый вопрос. Уточняй, если ответ неполный или противоречивый.

**Вопросы:**

1. Как называется ваш бизнес?
2. Опишите ваш бизнес в 2-3 предложениях: что это, для кого, какую проблему решает?
3. К какой маркетинговой нише относится ваш бизнес?
4. Какие основные продукты/услуги вы продаёте? Перечислите через запятую.
5. Есть ли второстепенные продукты/услуги?
6. Кто производит контент/продукты? Вы сами, команда, приглашённые эксперты?
7. Кто ваша целевая аудитория? Опишите 2-3 основных сегмента.
8. Какие задачи/проблемы решает ваш клиент, покупая у вас?
9. В какой географии работает ваш бизнес?
10. Как устроены цены? (диапазон, модель: подписка, разовая покупка, пакеты)
11. Как клиент заказывает и получает доступ? (процесс покупки)
12. Какие способы оплаты принимаете?
13. Через какие каналы к вам приходят клиенты?
14. Где ещё вы представлены в интернете? (сайты, соцсети, платформы)
15. В чём главные преимущества и ограничения вашего бизнеса?

### Этап 3: Показ пробелов

После интервью покажи пользователю:
- Какие поля остались незаполненными
- Предложи дополнительный раунд вопросов (опционально)

### Этап 4: Вопросы о конкурентах (до 10 вопросов)

1. Кого вы уже считаете своими конкурентами? Перечислите известных.
2. Какие особенности вашего бизнеса ОБЯЗАТЕЛЬНО должны быть у конкурентов?
3. Где и по каким критериям нужно искать конкурентов?
4. Сколько конкурентов нужно найти? (примерное количество)
5. Какую географию учитывать при поиске конкурентов?
6. Какой минимальный размер аудитории сообщества VK допустим?
7. Насколько свежими должны быть публикации у конкурента?
8. Кого обязательно включить в список?
9. Кого исключить? (кто точно НЕ конкурент)
10. Какие поисковые запросы использовать для нахождения конкурентов?

### Этап 5: Генерация карточки (draft)

Используй шаблон из `templates/business_card.md` и `templates/business_context.json`.

Выполни:
```bash
python scripts/generate_card.py --output-dir ./Субагент\ 1/Запуск_$(date +%Y-%m-%d)
```

### Этап 6: Подтверждение пользователем

Покажи пользователю карточку и попроси проверить.

**Если пользователь подтверждает:**
```bash
python scripts/confirm_card.py --input-dir ./Субагент\ 1/Запуск_YYYY-MM-DD
```

Обновит статус на `confirmed`, добавит дату подтверждения, синхронизирует Markdown и JSON.

**Если пользователь просит изменения:**
- Вернись к соответствующему этапу интервью
- Обнови данные
- Повтори генерацию и подтверждение

## Правила категоризации конкурентов

См. `references/card-structure.md` раздел «Правила категоризации конкурентов».

Кратко:
- **Прямые конкуренты** — продают тот же продукт той же аудитории
- **Косвенные конкуренты** — продают часть ассортимента или похожий ассортимент
- **Конкуренты за внимание** — могут отвлечь внимание клиента, закрывая схожую потребность

## Ожидаемые результаты

После подтверждения создай два синхронизированных файла:

1. **business_card.md** — понятная карточка бизнеса
2. **business_context.json** — машиночитаемый контекст

Оба файла должны:
- Содержать одинаковую информацию
- Иметь статус `confirmed`
- Иметь дату подтверждения
- Не содержать токенов или секретов
- Не содержать придуманных данных

## Условия остановки

Останови навык, если:
- Пользователь подтвердил карточку (статус: `confirmed`)
- Пользователь явно отказался от продолжения
- Произошла критическая ошибка (сообщи пользователю)

## Команды проверки

Выполни все проверки перед завершением:

```bash
# Проверка схемы JSON
python scripts/validate_json_schema.py --file business_context.json

# Проверка статуса
python scripts/check_status.py --file business_context.json --expected confirmed

# Проверка обязательных полей
python scripts/check_required_fields.py --file business_context.json

# Поиск токенов и секретов
python scripts/detect_secrets.py --file business_context.json
python scripts/detect_secrets.py --file business_card.md

# Проверка согласованности Markdown и JSON
python scripts/check_sync.py --md business_card.md --json business_context.json

# Итоговая проверка
python scripts/final_validation.py --dir ./Субагент\ 1/Запуск_YYYY-MM-DD
```

Все проверки должны пройти успешно.

## Ссылки на сценарии и справочные материалы

### Сценарии (scripts/)
- `generate_card.py` — создание Markdown и JSON из шаблонов
- `confirm_card.py` — подтверждение карточки, синхронизация
- `validate_json_schema.py` — проверка схемы JSON
- `check_status.py` — проверка статуса
- `check_required_fields.py` — проверка обязательных полей
- `detect_secrets.py` — поиск токенов и секретов
- `check_sync.py` — проверка согласованности Markdown и JSON
- `final_validation.py` — итоговая проверка

### Шаблоны (templates/)
- `business_card.md` — шаблон карточки бизнеса
- `business_context.json` — шаблон контекста бизнеса

### Справочные материалы (references/)
- `card-structure.md` — структура карточки, правила категоризации, подтверждения

### Тесты (tests/)
- `test_positive.py` — положительные тесты
- `test_negative.py` — отрицательные тесты

   [Файл не найден или статус не confirmed]

4. Изучаю источники через VK API...

## Примечания

- Навык не содержит данных конкретного бизнеса
- Навык не содержит токенов или секретов
- Навык использует относительные пути
- Все данные хранятся в рабочей папке пользователя
- Токены сохраняются отдельно и не включаются в итоговые файлы
